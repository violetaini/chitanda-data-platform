# 2.19.0 证书管理核验（2026-10-20）

- 新增三种证书来源、多份配置、按节点分配、续期检查、手动文件导入、实际加载指纹和离线待应用状态。
- 75 项后端测试通过，涵盖签名/nonce、TXT 引号及重试日志、保留无关 DNS 值、自动续期、DNS 证书变化去重、拒绝回退、异常保留原证书、状态对象回退并发、节点范围、私钥不回显及管理权限。
- 40 项系统设置界面检查通过，覆盖三种来源、文件控件、未保存内容保护、内部身份独立及桌面/移动端布局。
- 国内控制端真实完成 Let’s Encrypt 测试环境签发，验证域名与私钥匹配，最终验证 TXT 删除。测试证书未安装到业务节点，临时私钥已清理；生产 CA 证书未重复申请。
- DNS 面板安装指定订单导出组件；受限 API 账号仅授权现有业务所需订单。正常订单返回 200，其他订单及匿名访问被拒绝（现有 Nginx 将 403 对外映射为 404），没有授予管理员权限或放宽 PHP 沙箱。
- 正式业务配置使用 DNS 面板续签并同步。国内和香港两节点已加载订单证书，公开握手的 SHA-256 指纹均与中台一致；证书到期 2026-12-16。两端 Chitanda 通过新证书调用同步状态接口均为 200。
- 控制端备份位于 `/var/backups/chitanda-transit/certificate-profiles-*`、`certificate-fixes-*`、`final-certificate-maintenance-*`；DNS 扩展前路由与鉴权中间件备份于 DNS 服务器同目录的 `dns-cert-export-*`。保留账号、CA、管理白名单、原隧道与令牌，节点程序继续 2.11.1，未重装节点。

恢复时先备份当前私有状态，停用证书任务，再按备份恢复控制端源文件和对应证书配置；不可只恢复旧代码而遗留失配的新私有配置。DNS 系统可恢复备份路由并移除导出组件和权限文件；原证书订单与其续签配置无需删除。
