# 入口端口与自动选取

创建或编辑通道时，入口端口旁提供“自动选取”。新通道默认尝试分配；手动改过的数值不会被异步结果覆盖，已有通道不会自动改号。

自动选取按所选节点分别避开：其他通道已分配的入口（含暂停通道）、该节点的业务服务端口、中台协议端口、HTTPS 业务入口、管理端口，以及节点最近实际采集的 TCP 监听端口。范围为 1024–65535，从当前填写值开始查找。编辑时允许保留本通道自己已经监听的端口；不能借用其他通道的端口。

服务端口填写真实业务的监听端口；其已被业务程序占用正是正常状态，不会为它自动换号。双向通道分别在两个入口节点选取端口。

节点 2.9.2 在 Linux 上读取 `/proc/net/tcp` 与 `/proc/net/tcp6`，只上报 TCP LISTEN 的端口号，不采集进程名或业务内容。不需要安装 ss/netstat 等工具。所有 IPv4/IPv6 TCP 监听均保守避开。采集不完整、旧版本或节点离线时，面板明确显示“仅避开中台已有分配”，不会声称已经核验空闲。

保存时再次检查中台分配及最近节点上报；手动指定冲突端口返回 409。若其他程序在上报之后抢先占用，节点实际 bind 会失败，通道显示“入口端口异常”，展开后可看到占用原因；不会结束其他进程或静默更改端口。释放冲突后，节点可以在原端口恢复监听，也可编辑并重新自动选取。

这是基于心跳的空闲检查，不是操作系统端口租约。通常每 15 秒采集一次；建议与 bind 之间仍有竞争窗口，最终以节点成功监听为准。自动选取不会修改业务域名、目标服务或已有 URL 映射。
