# 隧道令牌（2.18.0）

创建单向或双向隧道自动生成 256 位随机业务令牌。每隧道独立、双向共用；编辑保留，删除撤回授权。合并保留第一条令牌并撤销另一条。已启用 URL 接入的隧道须先关闭此模式再合并或改变方向。

展开详情可查看、复制、隐藏或重置。令牌不进入 state 轮询和 CRUD 响应，只有登录管理员显式 POST 读取才显示。读取、重置校验管理来源、会话、Origin、CSRF，响应 no-store，日志和审计不记录令牌。隐藏、收起、切换页面和退出清除界面明文。

重置生成新值，增加配置版本并自动下发；节点应用后旧值失效。业务程序也须更新自己的令牌。控制端不可用时保留已认证缓存，离线期间无法保证即时撤销。正常心跳约 15 秒。

```http
Authorization: Bearer 本隧道令牌
X-Target-URL: https://真实业务域名/api/接口
```

入口按域名和令牌选择隧道的本地入口端口，同一 HTTPS 入口可服务多隧道。出口再次校验令牌和本方向允许的目标范围，直接访问真实业务。两端获得所需策略，纯中间节点不获得业务令牌及目标策略。

真实业务域名区分源站网站；可选固定 IP 只控制拨号地址，保留 Host、SNI 和证书验证。URL 模式不依赖原目标端口。现有 Chitanda 同步 API 支持同一个隧道令牌，调用方只配置一个令牌；其他业务仍须实现自己的鉴权。只有可信目标才能加入范围，避免将业务凭据交给不可信网站。

未启用 URL 接入的隧道保留旧固定端口方式。2.17 的源站适配器在当前 Chitanda 生产已停用；原始 TCP 流继续使用节点间协议身份。

详见 [HTTPS 接入指南](url-access.md) 和 [客户端补丁](../integrations/chitanda-header-url.patch)。
