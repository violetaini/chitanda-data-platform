# 隧道令牌（2.17.0）

创建单向或双向隧道时自动生成 256 位随机业务接入令牌。旧隧道首次升级自动补齐，保存在控制端私有状态文件；编辑保留原值，删除撤回授权，合并保留第一条隧道令牌并撤销另一条。每条隧道独立，双向共用。

数据通道展开详情可查看、复制、隐藏或重置令牌。平时不将令牌放入 state 轮询及 CRUD 响应；只有登录管理员显式 POST 读取接口才能查看。读取和重置均校验管理来源、会话、Origin 和 CSRF，响应 no-store，日志及审计不记录令牌。隐藏、收起、切换页面和退出登录清除界面明文。

重置产生全新随机值，增加配置版本并自动下发；入口节点应用配置后旧值失效。业务程序需要更新自己的令牌，控制端不会修改任意业务服务器环境。控制端不可用时节点保留已认证的缓存配置，因此离线期间不能承诺即时撤销。正常心跳约 15 秒。

调用方配置：

```dotenv
CHITANDA_SYNC_PEERS=https://你的业务域名
CHITANDA_TUNNEL_TOKEN=本隧道令牌
```

HTTP 请求只需 Authorization: Bearer 隧道令牌。业务程序原有的内部同步密钥保留在服务端，不再让接入方配置或发送。现有 Chitanda 客户端优先使用 CHITANDA_TUNNEL_TOKEN；未配置时兼容旧配置。入口校验隧道令牌，替换为独立下一跳凭据并删除调用方 X-Sync-Token；固定源站适配器注入本地配置的业务密钥，业务后台继续原有鉴权。来源 IP、Host/SNI、路径、方法和请求大小限制保留。

控制端仅向启用方向的源节点下发绑定域名、入口端口与令牌，不发给纯中间优化节点。入口需同时匹配 Host、固定回环目标端口与令牌；其他隧道令牌、已暂停/删除授权被拒绝。内置入口从当前节点配置热读取，外置适配器从专用授权文件逐请求读取。专用文件不含节点身份，节点原子更新；缺失、格式错误或空授权均拒绝。

新增业务仍需部署对应 HTTPS 入口与固定业务上游。令牌不替代业务接口实现，原始 TCP 流继续使用节点间协议身份。

Chitanda 业务客户端的最小兼容改动见 [集成补丁](../integrations/chitanda-single-token.patch)，包含同步请求、番剧缓存与封面请求的单令牌支持。
