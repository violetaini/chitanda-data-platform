# 数据通道自动故障转移

面板 2.25.0、入口节点 2.14.0 起，同一数据通道可以配置一条主线和最多八条有顺序的备线。每条备线可以串联多个优化节点，或使用两端直连。双向通道自动反转备线路径。

## 使用

1. 先在「节点管理」登记、安装优化节点，确认在线。既有入口节点先升级到支持故障转移的版本。
2. 打开「数据通道 → 编辑 → 自动故障转移」，点击「添加备线」。填写名称，选择经过的优化节点，需要更多节点时点击「串联优化节点」。
3. 使用上下箭头调整备线优先级。协议可以跟随主线，也可选择 H2、H3 或 Stream。通道两端沿用主线，无须再次选择。
4. 保存后，展开通道详情查看各方向的主线、备线健康状态及当前使用线路。系统拓扑同时显示备用路径。删除备线只移除备用路径，不更改业务入口。

例如，主线为「境内入口 → 境外入口」，备线为「境内入口 → 优化节点 → 境外入口」。业务仍请求同一个 HTTPS 域名，使用原来的隧道令牌、入口端口和业务目标。切换发生在源节点，不需要浏览器保持打开，也不依赖 DNS 改线。

## 选择与恢复

- 各条线路保持独立的加密连接和逐跳授权，探测完整路径是否确认到达出口；探测不发送业务请求。
- 小规模部署通常约每三秒探测一次，每节点最多四个并发探测；路径多或繁忙时排队。每次路径确认限时 1.5 秒。
- 新连接先确认出口收到通道握手，再发送业务数据；确认失败可依次换用其他备线。失败路径冷却五秒，后台继续探测。节点 2.14.1 起优先尝试未冷却的路径；它们均失败时仍尝试冷却路径，避免一次已过时的失败探测阻止实际可用的备线。
- 已切换后优先沿用当前备线，减少抖动。主线连续至少两次成功，且距离最近一次切换至少十五秒后，下一个请求优先使用主线。
- 面板显示节点最近一次心跳报告，通常比实际切换晚约十五秒；不能把报告到达时间当成网络切换耗时。过期探测不会继续显示为健康。

## 请求边界

URL 接入按 HTTP 请求处理故障转移。没有请求体的 GET/HEAD 可在网络错误时换线重试；小于等于 1 MiB 的响应在提交前缓冲，遇到截断可重试。未知长度的响应最多缓冲 1 MiB 加一个字节，超过后继续流式传输。读请求的响应头等待及缓冲阶段各有五秒超时；这不是所有业务的完成时间保证。

POST 等写请求只在尚未发送业务数据、通道握手失败时尝试其他路径。一旦开始发送，不自动重放，以免重复写入。已经返回部分内容的大文件、下载流或原始 TCP 长连接不能在另一条连接上原地续接，需要调用方支持断点续传或重连。业务可以另行使用幂等键处理写请求重试。

主备路径共用的入口、出口及业务服务器仍是共同故障点。该功能覆盖独立线路、中间优化节点等故障；整机高可用需要额外的入口、出口及业务部署。所有线路都不可用时返回失败，不绕过令牌或放宽目标范围。

## API 与权限

`POST /tunnel/api/v1/tunnels`、`PATCH /tunnel/api/v1/tunnels/{id}` 接受 `backupPaths`。省略表示保留；空数组表示删除全部备线。每项支持 `id`、`name`、`relayIds`、`transport`、`serverName` 和直连标记 `direct`。编辑时保留服务端生成的 `backup-…` 标识，调整数组顺序改变优先级。

```json
{
  "backupPaths": [
    {
      "name": "优化备线",
      "relayIds": ["optimizer-a", "international-endpoint"],
      "transport": "h2"
    }
  ]
}
```

当优化节点兼任端点时，仍须保留它在 `relayIds` 对应的首端或末端位置。普通两端直连备线可提交空的 `relayIds`，由控制端配置所需承接节点。每条物理路径最多八个承接节点，整个工作区最多 512 条主备物理路径。

备用路径沿用逻辑通道的目标范围，只有两端持有业务访问凭据。纯优化节点仅接收相邻节点的通道授权；状态接口不会返回这些凭据。节点删除保护覆盖备线路径。修改备线与反向路径在一次事务内校验，失败回滚。

## 验证

```sh
npm test
node scripts/failover-smoke.cjs
```

节点测试包含顺序重试、冷却与回切、跨目标拒绝、截断读响应重试、写请求不重放、大响应字节一致性和取消后的连接关闭。完整 H2/H3/Stream 集成测试须在 Linux 隔离环境执行；测试缓存使用临时目录。

发布时构建完整八架构目录，并确认服务实际使用的 `CT_RELEASE_DIR` 指向该目录；不要仅更新一个未启用的发布目录。保留控制端状态及节点程序备份，先升级入口节点，再添加备线。回退时先删除备线、确认主线可用，再回退节点程序；不得让旧入口将物理备线误当作独立监听端口。
