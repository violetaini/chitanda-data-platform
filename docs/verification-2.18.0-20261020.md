# 2.18.0 核验（2026-10-20）

面板 2.18.0，节点引擎 2.11.1。新增按隧道令牌和 X-Target-URL 分发 HTTPS 请求，目标范围按隧道方向维护并自动下发。

## 测试

- 后端 68 项通过，覆盖管理权限、目标校验和共享入口授权。
- 隧道及资料 UI 114 项、使用指南 54 项通过，包含桌面、移动端、动态目标及未保存表单保留。
- 独立入口 Go 测试通过。Linux ARM64 引擎 28 个顶层测试组通过，包含真实 H2、H3、Stream、串联、请求头分发、完整响应及 304。
- 8 种 Linux 架构构建完成并生成校验值；Chitanda 原业务及同步、缓存客户端测试通过。

## 生产

- 四台节点升级至 2.11.1，保留身份、配置和自动更新定时器。
- 双向业务隧道启用 URL 模式，每方向只允许既有 www 业务域名 `/api/sync/`，集中固定到对应源站；保留原令牌。
- H2 两方向各连续 12 次状态请求返回 200，越界目标 403、HTTP 目标 400、错误令牌 401。
- 国内、国际 Chitanda 实际执行同步均为 200、对端成功。客户端已配置目标域名。
- 两端旧源站转接服务停用、禁用，专用源站域名配置移除；之后状态及缓存请求仍返回 200。业务数据保留，旧配置保留私有备份。
- 临时 Stream 隧道无独立 DNS 绑定，使用同一个 HTTPS 入口及不同令牌，两方向业务请求均为 200。原目标端口设为不可用值，确认 URL 模式不依赖它。测试隧道随后删除。
- 公网 H3 在 data-test 与原 control SNI 下均未形成底层节点通道，返回 channel unavailable，原因未定。软件 H3 测试通过不能代表当前公网 UDP 路径可用。生产维持 H2。
- 全部临时隧道已清理，保留用户原有两条。未修改 DNS、CF、管理来源限制、账号或 CA。

## 恢复资料

控制端备份：`/var/backups/chitanda-transit/header-url-*`、`header-flush-engine-*`、`final-header-ui-*`。业务源码、Nginx、环境变量及退役适配器分别备份于同目录的 `native-header-business-*`、`header-client-switch-*`、`retired-origin-adapter-*`。

2.11.1 修复 framed H2 响应排队时过早关闭引起的截断：结束写入并等待对端消费，再关闭连接，设置有界等待并加入回归测试。请求与响应保持流式处理。
