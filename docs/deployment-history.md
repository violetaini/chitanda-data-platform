## 部署与边界

- 面板：`https://control.chitanda.net/tunnel/`，直接解析至国内服务器 `110.42.32.161`；域名根地址在来源校验后跳转进入面板。
- 2026-10-17 用户确认公网出口变更后，将唯一授权公网 IP 从旧地址替换为当前 `123.119.187.76`，旧地址已移除。`control.chitanda.net/` 现在通过独立 `transit-control-root.conf` 在来源检查后跳转至 `/tunnel/`，解决原根路径 404；原后台其余路径及 IP 虚拟主机根入口不改。`/tunnel` 同样规范到带斜杠地址。根入口不能使用早于访问校验的直接 Nginx return，以免未经来源校验就跳转。
- Host 转发优先使用包含显式端口的请求值；普通 Host 字段为空时回退到 Nginx 的有效主机名，避免后端默认成 `127.0.0.1:5092` 而拒绝正常 Origin。用于回退的 location if 只执行 set，不返回内容，不绕过来源检查。出口 IP 变化需由用户确认后同步 Nginx、`CT_ALLOWED_IPS` 与部署配置，不通过关闭访问限制解决。
- 面板和全部管理 API、脚本、样式仅允许来源 `123.119.187.76`、`127.0.0.1`、`::1`。Nginx 和应用分别校验；应用仅监听 `127.0.0.1:5092`，不开放公网管理端口。
- 首次部署使用现有网站后台环境配置中的管理员账号和 scrypt 密码哈希初始化独立面板登录，之后独立管理；重新部署保留面板现有账号和密码哈希。2026-10-17 已按用户要求单独重置面板密码并验证登录，原网站后台配置未改动。登录会话与原后台隔离，使用 HttpOnly / Secure / SameSite=Strict cookie，写请求要求 CSRF token；错误登录有次数限制。
- 机器接口为独立路径 `/transit-node/sync`，不提供面板或管理操作，只接受 POST 并先校验自动生成的节点 ID 与独立凭据。为允许新机器自动接入，此机器接口不使用固定来源 IP 白名单；认证通过后从 Nginx 覆盖的实际来源头识别服务器出口地址，忽略用户填写的地址与 ID。该变化仅作用于机器接口，`/tunnel` 和 `/tunnel/` 的双层面板来源白名单保持不变。
- 不相信客户端自行提交的 X-Real-IP / X-Forwarded-For。现有 Nginx 只信任本机 stream listener 提供的 PROXY protocol 来源；面板 location 用 `$remote_addr` 覆盖提交给应用的来源头。
- 当前只有 `110.42.98.254` 与 `47.243.148.109` 承担通道。国内杜甫 `110.42.32.161` 是控制端与国内业务源站；`168.138.209.1` 是新国际业务源站；`23.145.248.44` 保留原网站和 DNS，旧测试通道程序已停用。支持登记多个优化节点，每条通道独立选择节点、H2 / H3、SNI 和端口；现行测试使用 H2。v2.3 香港公有 HTTPS 接入与通道共用一个 Go 进程。

## 数据路径

```text
国内杜甫业务副本 5093 → HTTPS → 110.42.98.254
  → Chitanda H2 / TLS 1.3 → 47.243.148.109
  → HTTPS → 168.138.209.1 → 回环 5081 业务副本

168 业务副本 5081 → HTTPS → 47.243.148.109
  → 已建立的 H2 通道 → 110.42.98.254
  → HTTPS → 国内杜甫 → 回环 5093 业务副本
```

建立两条源监听 15082 / 固定目标 16082 的测试通道，**没有修改生产后台 `CHITANDA_SYNC_PEERS`、同步白名单或同步令牌**。副本使用独立业务同步令牌与按方向划分的网关凭据；peer host / port 白名单精确限定到测试域名与 443，没有删除 SSRF 校验。副本的公开产物与可写数据目录与生产分开，正式切换前必须重新补齐最新数据。

源监听及目标服务连接固定为回环地址，不能指定任意目标 IP；控制台管理端口 5092 不能作为隧道目标。隧道支持新建、编辑、暂停、删除，可改中转、协议、SNI、源端口和目标端口。优化机的 Chitanda server dial hook 仅接受虚拟地址 `bridge.internal:1`。broker 另校验节点令牌、线路来源、协议、SNI 和启用状态，不同传输链路的待接入连接池相互隔离。

H2 / H3 直接使用上游 Chitanda SDK 和服务端库，固定源码提交 `2926cf2c41c85d2177536a4ba2d9931f1ec675f9`。H2 使用 TCP，H3 使用 QUIC / UDP；优化机同一配置端口监听 TCP 和 UDP。两者均为 TLS 1.3，禁止关闭证书验证。SNI 默认 `control.chitanda.net`，可自定义有效域名；控制端保留独立工作区 CA 私钥，按优化机与所有关联隧道的 SNI 自动签发服务器证书，并通过该优化机自己的认证配置接口下发。接入程序仅获得 CA 公共证书，不获得 CA 私钥或优化机私钥。优化机使用动态证书回调加载更新，不能用不匹配的 SNI 完成 TLS 握手。

工作区 CA 位于国内私有状态目录的 `pki/`，有效期十年；服务器证书有效期一年。服务器证书在 SNI 配置变更时自动重签，节点进程在启动时通过 `SSL_CERT_FILE` 信任工作区 CA，仍保留系统公共根证书。增加优化机无需另行安装面板或 CA 私钥。更换工作区根 CA 需要重新下发接入配置并重启节点进程。控制接口仍使用现有网站的公共可信证书，并固定连接国内源站。

加密在优化节点处终止，优化机可以接触其转发的业务字节。需要对优化机隐藏正文的服务应继续在业务两端使用 HTTPS 等端到端保护。

## 数据中台管理与个人设置（v2.1）

页面风格沿用主站 `assets/css/base.css` 的暖白纸面、樱粉、浅紫、衬线标题和圆角卡片。登录页、导航、状态、表单及历史记录展示统一使用数据中台管理用语。内部协议字段、节点配置路径不改名。

favicon 复用 `site-shell-config.ts` 所指主站 ICO 的原始文件；PNG 来源为 `admin/public/favicon.png`，品牌图片来源为 `assets/media/studio/rv.webp`。资源存放在独立面板 `public/` 并同源提供，不放宽 CSP 或 IP 白名单。2026-10-17 按用户要求再次重设独立账号密码，面板密码最小长度同步为 8 位；原网站后台密码规则不变。所有凭据只存哈希，不在文档或项目日志记录明文。

侧栏「个人设置」或头像入口可修改登录用户名、密码并上传 / 恢复头像，手机导航也提供该入口。修改用户名或密码需填写当前密码；新密码至少 8 位，两次输入一致，用户名为 3–64 位中文、字母、数字或 `_ . @ -`。保存后所有会话立即失效，需要重新登录。只修改用户名时新密码可留空。

账号首次从独立面板环境初始化，后续以 `/var/lib/chitanda-tunnel/account.json` 为准，文件权限 `0600`，归面板服务用户所有。该文件单独存储用户名、scrypt 密码哈希、头像和头像版本，既不进入节点配置，也不随数据通道配置版本变化。部署和重启保留该文件；重新修改环境变量不会覆盖已保存的账号。原网站后台账号不受影响。紧急恢复时由 root 停止面板服务，私下备份此文件，更新其中 `username`、`passwordHash`（只写新生成的 scrypt 哈希或已授权的恢复哈希，保留头像字段），再启动服务；禁止把明文密码写入文件或命令参数。

头像仅接受最大 2 MB 的静态 PNG / JPG / WebP。国内面板使用固定版本 Sharp 解码、限制像素、裁剪并重新编码为 256×256 WebP，去除原文件元数据；不保存原文件或 SVG。头像读取和修改都要求登录，修改要求 CSRF，全部继续受面板的 Nginx / 应用 IP 白名单限制。面板 HTTP 请求上限 3 MB，仅头像 JSON 放宽到约 2.9 MB，其余 JSON 仍为 128 KB。Sharp 只安装在国内面板，优化机不新增依赖。

验证命令 `node scripts/tunnel-control-account-smoke.cjs` 覆盖修改账密、全部会话失效、重启保存、头像解码与移除、IP / CSRF 以及桌面 / 手机设置页。账号设置表单不会被五秒自动刷新清空。部署脚本同时保存旧版面板源码归档、环境配置和已有账号私有备份。

## 文件与服务

### v2.2 自动图表与访问保护

面板文字使用 `Times New Roman, STKaiti, 华文楷体, KaiTi, serif`，不复制或公开分发系统字体。数据动态参考 [AdGuard Home 的 Line 组件](https://github.com/AdguardTeam/AdGuardHome/blob/master/client/src/components/ui/Line.tsx) 的单调曲线、渐变面积与悬停读数思路，使用面板自己的 SVG 实现，无新增 React 或图表运行时依赖。横轴按真实时间，纵轴自适应 B/s / KB/s / MB/s；采样间隔超过 45 秒、程序重启或计数器回退均产生缺口。1 / 5 / 15 分钟切换只筛选已有采样，重启后的空缺不补造。

`/api/state` 的 `topology` 根据已登记节点、管理服务和通道关系实时生成，前端根据图关系计算布局、消除节点重复并合并双向边。未分配节点始终保留，节点名称、数量、ID、地址和边均来自当前配置，缩放与适应画布在运行时完成。

`/var/lib/chitanda-tunnel/login-defense.json` 是独立持久防御记录，服务用户 `0600`。同一来源最多一个、总计最多两个密码校验并发；登录和账号设置分别限制每来源每分钟 12 次验证。第二次失败起逐步冷却，单来源 15 分钟内 5 次失败锁定 15 分钟，持续失败按 30 分钟、1 小时等逐级延长，最长 24 小时；跨来源按同一管理员账号累计，10 次失败同样锁定，改变填写的用户名不能绕过。锁定跨服务重启保留，HTTP 429 返回 Retry-After，前端显示重试倒计时。当前密码设置使用独立验证计数，表单格式错误不计为密码错误。验证记录只保存时间、来源、验证类别与结果，不保存密码或尝试填写的用户名。

会话仍为 12 小时绝对有效期，最多 32 个，同时绑定创建会话的来源地址；修改账密撤销所有会话。浏览器写请求校验 Origin / Fetch Metadata，管理写请求同时要求 CSRF 和 JSON，机器接口只接受独立节点凭据。新 `/api/security` 和所有脚本、图标继续受登录 / 白名单边界保护；机器凭据不能访问管理 API。

内部校验凭据为 HMAC-SHA256：以节点上报凭据为密钥，以 `chitanda-broker-v1:<优化节点ID>` 为上下文。每个业务节点 / 优化节点组合独立派生，不能用该派生值调用上报接口或冒充其他优化节点的校验身份。优化节点配置仅包含本节点通道涉及的节点派生值，不包含业务节点的上报凭据。接入程序仅获得自己的相关优化节点派生值。程序缓存通过 `credentialVersion=broker-v1` 迁移并保存在既有私有运行文件中；三端需要一起升级到 v2.2。优化节点仍为一个 Go 可执行文件，没有新增面板、数据库或其他服务。旧备份可能包含历史原始凭据，备份目录必须保持 root 私有。

校验命令：`node --test scripts/tunnel-control-security.test.cjs`、`node scripts/tunnel-control-dashboard-smoke.cjs`，以及原有功能 / 账号回归。防爆破锁定和模拟图表只在隔离数据目录测试，不对线上管理员执行错误密码压力测试。权限检查覆盖会话来源、CSRF、跨来源、机器 / 管理边界、无关节点排除、不同优化节点派生值不同及派生值无法用于上报。实际 H2 / H3 集成同时验证控制端凭据不能作为内部校验凭据使用。

v2.2 增量发布使用 `python scripts/upgrade-tunnel-control-v22.py`：先确认三端可维护并备份私有账号 / 状态与面板源码，再更新变化文件、检查并更新 Nginx，最后升级三端程序及独立校验配置。Nginx 保留原始 Host authority（包括显式端口），使同源校验支持合法的带端口维护入口；来源地址仍由 Nginx 覆盖转发。运行缓存必须匹配凭据版本、节点身份与至少当前配置版本，旧版缓存不能恢复历史控制凭据。

只读权限复核为 `python scripts/verify-tunnel-permissions.py`，检查三端私有文件 `0600`、服务用户 / systemd 限权、上报身份保持不变、专用校验作用域、缓存迁移、接入端无服务器私钥，以及面板仅监听回环地址。脚本只输出检查结果，不输出密钥。

优化机不安装面板、Node、数据库或 Docker。程序通过 systemd 运行，`GOMEMLIMIT=32MiB`、`GOMAXPROCS=1`，进程组内存上限 96 MB。初版及 H2 常驻内存观测约 10–16 MB，H3 和更多并发链路会增加实际占用。每个「中转 ID / 协议 / SNI」组合复用独立客户端，并保留两个待接入通道，仅为本节点实际参与的已启用线路建立链路；未使用的优化机不占接入端连接资源。接入端最多处理 32 个主动本机连接，中转 broker 上限 96 个连接，超限拒绝。所有 TCP 转发保留半关闭语义。

节点每 15 秒上报心跳并拉取配置。节点在线表示最近 50 秒有有效心跳；线路就绪还要求源监听、两端对应协议 / SNI 链路探测正常，以及源端、目标端、中转端都确认最新配置版本。配置尚未确认时显示「配置同步中」，避免复用旧链路状态提前显示就绪。速率和资源来自实际程序；曲线按中转区分，保留控制进程内近期采样，重启重新采集，操作记录持久化保留最近 150 条。协议 / SNI 或中转变更可能重建连接；暂停和删除配置会在后续节点同步时清理相关连接。

节点 ID 自动分配，服务器出口地址从认证心跳获取，不提供手工输入地址或 ID 的表单。支持编辑节点名称和优化机默认 SNI。删除节点若有关联隧道，必须明确确认级联删除，控制端立即移除凭据并拒绝旧令牌；在线节点在下一轮配置同步时关闭相关连接，删除的节点也会关闭本机监听和传输客户端。此操作删除登记与连接权限，不远程卸载服务器上的程序。

控制端临时停止不会中断已配置线路的数据转发；节点保留最近成功配置用于恢复。首次注册需要控制端可达。支持在面板中手动选择不同优化机，当前不做自动故障切换，也不提供任意服务器的远程安装。

## 操作与验证

## 访问与回滚

从授权家庭网络访问 `https://control.chitanda.net/tunnel/`。如果浏览器把该域名流量转经其他出口，服务器看到的将是该出口地址，返回 403 是预期行为；需让该域名直接连接国内源站。

本机维护入口为 `http://127.0.0.1:5092/tunnel/`；浏览器正常使用 HTTPS 公网受限入口。不要对外映射 5092 端口。

停用独立系统可分别停止 `chitanda-transit-panel` 和三端 `chitanda-transit`，不影响原有网站同步。恢复 Nginx 时使用部署时间对应备份，检查通过后 reload。保留状态与配置文件以便恢复，不自动删除证书、密钥或状态数据。
