# 2.15.0 / 节点 2.9.0 实测记录

2026-10-20：国内端、国际端、优化机分别选择，各项均可不使用；至少两台不同服务器，不再默认插入优化机。端口名称由节点用途及方向生成；支持正向、反向和双向。域名、TTL、SNI 继续折叠。参考了 [哆啦 A 梦面板的入口/出口配置与转发模式](https://github.com/bqlpfy/flux-panel)，实现沿用本项目已部署的 Chitanda 协议及鉴权模型。

## 验证

- 58 个后端测试通过；增加双端点配置、双向原子保存、旧节点能力限制、私钥隔离、暂停时撤回监听和错误反向端口回滚断言。
- 83 项隧道/账户 UI 检查及 12 项通道测活 UI 检查通过；覆盖不选优化机、不选国际端、不选国内端、反向两端直连、串联及保留旧反向优先双向隧道的身份、端口、SNI。
- Linux ARM64 实际运行 17 组节点测试；新增端点监听启动/关闭/再次启动，以及 agent 身份在本节点承接反向流的覆盖。保留 H2/H3/Stream、证书、数据完整性、越权和串联测试。
- 构建全部 8 个既有 Linux 架构；生产发布逐个核对 SHA-256 与大小。四台已安装节点升级到 2.9.0，安装配置保持原样，自动更新任务仍启用。

## 真实服务器

使用已授权节点实测五种组合：国内 ↔ 国际、国内 ↔ 香港优化机、香港优化机 ↔ 国际、国内 ↔ 香港 ↔ 国际、国内 ↔ 香港 ↔ 第二优化机 ↔ 国际。每种组合分别测试 H2/H3/Stream、双向及两个并发的 256 KiB 数据，检查落地点、长度和 SHA-256。

首次普通端点监听建立期间，正向 H2 与 Stream 各一次测试批次未就绪；待链路建立后两批重试通过。最终全部 30 个方向/协议组合成功，共 60 次确认的数据事务、15 MiB。暂停三个普通端点直连通道后，国际端 18443/TCP 与 11323/TCP 均关闭；重新启用后，三个协议的两个方向再测 12 次、3 MiB，全部通过。

节点用途和安装身份没有被改为优化机；私有端点监听配置由通道按需生成。普通直连的两个端点均须上报支持能力，旧版本不会拿到可能被误读的配置或新对端凭据。只有相关节点获得固定路径所需的相邻配置。未增加第三台承接服务器，也不会自动绕过指定中间机。

## 收尾

15 条临时通道、三台临时回环服务均已移除；不再使用的国际端认证监听已关闭。原有三条通道、源站、设置、域名、节点身份、账户和管理 ACL 保留；配置版本 92。国内及 168 的原 Chitanda HTTPS 业务 URL 均返回 200 / TLS 1.3。

直连仍受实际公网质量影响，不保证优于经过优化机；此版本没有新增自动选路或故障切换。原始入口/服务端口保持回环，公开业务 URL 继续使用独立业务域名和固定上游。
