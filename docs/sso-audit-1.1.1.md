# SSO 1.1.1 安全复查

日期：2026-10-21。范围为统一身份服务源码、浏览器操作、OIDC 与中台联测、生产运行权限及依赖公告。面板保持 2.23.0。本次不是生产压测，没有对真实账号执行爆破或更改真实密码、绑定认证器。

## 确认并修复

| 问题 | 触发条件及影响 | 修复 |
| --- | --- | --- |
| 刷新令牌重放分支早于客户端鉴权 | 持有已消费刷新令牌但没有客户端密钥的人，可触发对应统一会话撤销 | 先校验实际客户端及密钥，再执行重放撤销；错误客户端不能撤销会话 |
| 动态验证码消费记录只在内存保留 60 秒 | 重启会清空记录；允许未来一步验证码时，有效窗口可能超过 60 秒 | SQLite 持久化消费摘要、原子唯一约束，保留 90 秒，过期清理；原验证码不落库 |
| 登录使用异步密码校验前的两步验证状态 | 另一会话在等待期间启用或修改验证器时，旧登录请求可能使用过时状态 | 校验结束后重读密码和两步验证状态，发生变化即拒绝；已启用却缺失密钥时拒绝登录 |
| 关闭两步验证缺少异步后的会话核验 | 请求读取后会话被撤销，等待密码校验的旧请求仍可能修改验证器 | 密码校验后再次核验会话及凭据；关闭必须同时验证未使用动态码 |
| 验证器设置缺少密码复核、其他旧会话仍存活 | 已有浏览器会话可直接设置验证器；其他旧会话未重新认证 | 设置前复核密码并限制次数；生成二维码后复核状态；启用或关闭会撤销其他会话 |
| 不存在账号跳过密码哈希计算 | 响应时差可辅助枚举账号 | 同等成本的随机虚拟密码哈希计算，统一失败响应 |
| 同日过期会话仍显示活跃 | SQLite 日期格式与 ISO 日期直接比较不一致 | 统一使用 ISO 时间比较 |
| UTF-8 字符跨请求块时损坏 | 多字节中文恰好被网络拆开 | 有界累积 Buffer 后统一解码；保留 64 KiB 大小与请求超时限制 |
| 回调注册与回调使用校验不同 | 可登记实际上不允许的 HTTP 或带用户信息回调 | 两处复用精确回调规则，仅 HTTPS 或本机 HTTP，无账号密码和片段 |

修改密码的旧、新密码均限制为最多 4096 字节，并在耗时校验后复核凭据状态。两步验证操作采用密码输入框，取消后清空输入，密码和动态码不放入 URL、浏览器存储或日志。

## 验证

- SSO 12 项安全测试通过，包含隔离子进程复现并发状态变化、刷新令牌错误客户端与重放、登录锁定、跨重启记录、失效会话、损坏验证器和请求块边界。
- 真实 SSO 与面板的 OIDC 联测通过，覆盖 PKCE、精确回调、来源与 CSRF、令牌用途隔离、管理员授权及统一会话撤销。
- Playwright 验证启用、密码复核、二维码确认、关闭时双重验证，页面无脚本异常。
- `npm audit --omit=dev` 在检查时没有报告已知生产依赖漏洞。
- 生产服务使用专用低权限用户，回环监听；环境、数据库、私钥 0600，数据目录 0700，启用只读系统目录与内存限制。SSO Cookie 仍为 Secure、HttpOnly、host-only `__Host-` Cookie。
- 上线后核验服务 1.1.1 正常、匿名管理 API 返回 401、跨站写入返回 403，公网 HTTPS 安全头生效；国内经独立香港 TLS 路径获取 JWKS 成功，香港机房来源访问登录页与门户均返回 403。

生产发布前使用 SQLite backup API 备份数据，保留原账号、会话、签名私钥和客户端凭据。新表为增量创建，不替换数据库。源站子网拦截、IDC 拦截和必要认证后端路径保留。

## 需要继续维护

检查时管理员尚未启用两步验证，需要账号持有人在身份门户绑定自己的认证器，并使用独立的长密码。本次没有替用户启用或接管验证器。

Node.js 当前运行 22.23.3。官方在 [10 月安全发布预告](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) 中说明 22.x 将有最高 HIGH 级别修复；本次查询[官方发行索引](https://nodejs.org/dist/index.json)时最新 22.x 仍为 22.23.3，补丁尚未出现在索引中。补丁发布后仍需校验校验和、运行兼容测试并升级，不能把 npm 依赖审计结果等同于运行时不存在风险。

验证码只接受一次的设计依据 [NIST 数字身份指南](https://pages.nist.gov/800-63-4/sp800-63b.html)；客户端绑定与刷新令牌保护参考 [OAuth 安全最佳实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)。源码审查、回归测试与 WAF 不能保证消除所有未知漏洞；IDC 覆盖依赖 IP 数据库，网络层大流量攻击仍依赖基础设施防护。
