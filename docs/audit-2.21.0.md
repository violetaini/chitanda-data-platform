# 2.21.0 审查与验证范围

检查控制端鉴权、来源 ACL、CSRF、密钥边界、节点配置分发、隧道生命周期、业务 URL 目标权限、证书元数据与私钥隔离、界面刷新及生产依赖。

确认并修复：

- 公网地址校验不统一，部分回环、共享、保留地址及 IPv6 本地地址可被识别为公网地址。控制端节点地址识别和固定回源校验统一使用明确阻止规则；合法现有公网地址继续使用。
- 删除节点时，关联隧道和 HTTP 策略/令牌清理曾依赖后续状态读取。现在同一次删除中清理整个隧道分组和凭据，并严格检查 cascade 布尔值。
- 重复暂停/启用原状态会重复增加全局配置版本，导致无意义的节点同步。仅更新 enabled 时现在保持幂等；拒绝字符串等非布尔值。

新增管理 API 使用单独的高随机度密钥，仅存摘要，默认只读，支持分项权限、过期、撤销与限流。API 入口沿用面板来源 IP 限制。明确映射资源，不能通过管理密钥进入账号、DNS 私钥、安装凭据或密钥签发接口。请求体读取结束前再检查密钥是否仍有效，写入审计包含调用者 ID。

验证包括全部 Node 后端及界面检查、业务 gateway Go 测试、节点引擎 Linux 测试和 npm 生产依赖审计。节点引擎测试在临时 mount namespace 和 nobody 用户下运行，将测试的固定运行目录映射到临时目录，不写生产节点目录；Windows 的端口占用错误文字与 Linux 不同，因此以目标 Linux 环境结果为准。未修改或替换生产节点引擎。

这是本次代码与集成检查的范围，不等同于外部渗透测试或“没有任何漏洞”的保证。

本次验证结果：83 项 Node 后端检查、407 项界面检查通过；gateway Go 测试通过，节点引擎的 Linux 隔离测试通过；npm 生产依赖审计为 0 项已知漏洞。另核对了现有 Nginx 来源地址映射，保留边缘校验与管理来源限制。

线上 2.21.0 复核：现有账号、访问规则、证书、路由、隧道及业务配置保持一致，配置版本仍为 119。使用临时只读密钥验证 status、nodes、tunnels、OpenAPI 均为 200，HTTPS 经 Nginx 的证书验证和鉴权通过；无密钥、非授权来源、只读写入与管理接口越权均被拒绝。临时密钥已撤销，撤销后调用返回 401。
