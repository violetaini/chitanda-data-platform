# 统一证书与原生 Stream（2.7.0）

## 管理方式

节点页展示身份、状态和资源；业务域名与解析状态在隧道中展示。入口能力来自节点本地 `dataGateway` 或 `httpsIngress` 配置，不按节点 ID、地区或 IP 硬编码。新增外置入口时在该节点的启动配置中登记 `httpsIngress`，不改前端。

系统设置的 SSL 证书主表单直接配置 HTTPS 业务证书；内部通道证书位于高级设置，不再需要选择“证书用途”。底层仍区分两种证书，以保留已有配置及严格验证：

- 数据通道：默认用当前工作空间 CA 自动签发与续期；也可导入匹配所有 TLS 线路 SNI 的公开受信任完整证书链及私钥。修改线路 SNI 时检查覆盖范围。TLS 最低版本 1.3，严格校验，用户无需配置开关。
- HTTPS 业务入口：“使用节点现有证书”沿用各节点原有证书源，续期由原 DNS / 证书系统负责，中台读取并应用更新，不表示由中台申请公网证书。自定义模式导入完整证书链 / 私钥并显式选择应用节点；必须覆盖所选节点实际入口域名。私钥不会从管理接口返回，只进入所选节点的认证配置。切回自动模式恢复本地证书源。

只接受公开根或当前工作空间 CA 可验证的证书链，校验证书有效期、服务器用途与私钥匹配。自定义证书需管理员在到期前替换，自动模式继续由已有 DNS 证书系统续期。节点上报的证书详情集中在系统设置，不放在节点卡片。

## 国内外置 HTTPS 入口

国内节点上 Nginx 仍承接原入口，来源白名单、认证、路径和业务端口不变。节点读取 `httpsIngress` 中本地管理员指定的引导证书，将有效证书 / 私钥原子写入一个 0600 的 `bundle.pem`；Nginx 的 certificate 和 certificate_key 均指向该文件。

`external-https-cert-sync.py` 通过 root 拥有的固定 JSON 配置每 15 秒同步原 DNS 证书源到引导文件，并在 bundle 变化时执行 Nginx 配置检查及重载。它不执行控制台提供的命令，不允许节点修改 root 配置，节点进程仍无 root 权限。相关 service / timer 模板随仓库提供。香港内置入口用内存证书热更新，无需此辅助服务。

## 原生 Stream

线路选择 `Stream · 原生加密流`，源 / 目标仍为固定节点的本机回环服务端口。中转客户端选择上游 SDK 的 `TCPTransportStream`，服务端使用 `NewStreamServer`，保留原生加密认证、重放防护，并绑定优化节点身份。没有将普通明文 TCP 伪装为 Stream。

Stream 独立使用 TCP 11323（机器配置支持 relay.streamPort），与 H2 TCP443 / H3 UDP443 共存；它不使用 HTTPS、TLS 证书或 SNI。国内源站到国内节点的现有 HTTPS 业务入口与此为不同层次，保持原业务接入方式即可。

香港本次部署的 `chitanda-stream-guard` 只允许当前国内数据节点及回环访问 TCP11323。新增优化机 / 接入机时，需在对应防火墙开放所需节点来源；不得开放管理端口。应用层继续校验 PSK、优化机身份与节点派生凭据。当前尚未默认把生产 H2 线路改为 Stream。

## 验证与恢复

升级前备份控制端源文件、账号 / 状态 / 测活记录，以及两节点程序、启动配置和缓存；国内额外备份 Nginx 入口配置。回滚需同时恢复国内 Nginx 证书路径与对应节点配置，停用新增证书同步 timer；恢复节点程序时保留身份凭据与工作空间 CA。

测试包含真实 Linux H2/H3 / SNI、Stream 大数据半关闭、错误 PSK / 节点身份拒绝、无业务负载测活、证书热轮换与自动源恢复。控制 API 检查来源、会话、CSRF、完整链、域名覆盖、私钥不回显与节点分配范围。UI 验证桌面 / 手机无溢出和协议字段切换。
