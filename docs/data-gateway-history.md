## 迁移副本

旧国际机向 168 直接复制网站公开产物和后台程序，共 2993 个文件、1,569,867,472 字节（复制完成时统计，不含后续生成缓存）。校验所有公开产物内容后，仅 sitemap.xml、bangumi-sync.json 和 content-cache.json 三处运行数据有差异，其余静态文件一致。SQLite 使用在线 backup API 生成一致性快照，两端副本 integrity_check 均为 ok。

两端业务副本均位于 `/www/chitanda-migration-20261017`，公开产物在 `dist-astro/`，内容库在 `data/content.sqlite`，可写媒体在 `assets/`，与生产目录无共享硬链接。国内副本只监听 127.0.0.1:5093，新国际副本只监听 127.0.0.1:5081。systemd 单元为 `chitanda-migration.service`，使用独立低权限账号、NoNewPrivileges、ProtectSystem=strict、仅测试目录可写及 512 MiB 内存上限。

新国际站已具备 Node 22 ARM64 与 ffmpeg；首页、后台登录页、内容接口均正常，未登录管理会话返回 401。原环境中“一言/歌单使用本机 API”的设置在新机不可直接照搬：新机未迁移独立 api.chitanda.net 服务，副本改为调用现有 HTTPS API，两项运行接口已验证 200。DNS、独立公共 API、CDN 与其他项目没有搬迁。

生产网站域名尚未切到 168，生产库和两个原网站的同步配置均未更改。测试完成后恢复副本原账号配置，移除临时测试账号的生效配置并清理测试记录与媒体；独立同步凭据和测试副本保留，以便继续验证。临时 rsync 身份仅允许旧国际来源、只能写入迁移目录，复制核对后已删除目标授权行与源机临时密钥。

## 真实同步结果

使用副本正常管理员接口新增项目，触发程序自带事件同步和文件 prepare/chunk/complete 流程；随后修改并删除项目，核对另一端实体、修订号与删除标记。未绕过程序向目标数据库写测试内容。

| 方向 | 图片字节 | 分片 | 新增及文件核验耗时 | 结果 |
| --- | --- | --- | --- | --- |
| 国内至新国际 | 1,246,586 | 512 KiB × 2 + 尾片 | 6.250 秒 | 新增、修改、删除、文件与公开副本 SHA-256 一致 |
| 新国际至国内 | 1,246,586 | 512 KiB × 2 + 尾片 | 5.750 秒 | 新增、修改、删除、文件与公开副本 SHA-256 一致 |

耗时包含后台写入、自动调度、跨境数据与检查轮询，为单次观测，不是持续吞吐或 SLA。后台已有同步逻辑新增可选 CHITANDA_SYNC_GATEWAY_TOKEN：外层 Bearer 和内层 X-Sync-Token 独立；不设置新变量时沿用旧行为。番剧缓存与封面查询也支持同样的可选外层鉴权。

修正角色后的丢弃式摘要测试还核验了双向 4 KiB、512 KiB、2 MiB 完整性。国内至 168 的 2 MiB 单次约 0.600 秒，反向约 13.217 秒；原站直连 512 KiB 在国内至 168 方向发生超时，反向直连约 2.640 秒。不同体积与时段明显波动，不能据此承诺优化链路始终更快。

## 接口与权限边界

- 面板继续只允许 123.119.187.76、127.0.0.1 和 ::1；旧授权 IP 被拒绝。118 项入口 / 静态资源 / API 来源检查通过，业务节点不因此获得面板访问权。
- 国内业务入口仅接受杜甫来源，香港业务入口仅接受 168 来源和本机；检查实际 TCP 来源，不相信客户端转发头。香港公有 HTTPS 和原通道由 SNI 精确区分。
- 各方向、各跳点使用不同 Bearer 凭据，按跳替换，最终后台不接收外层凭据；业务同步令牌为本轮副本独立生成，不使用生产同步令牌。
- sync 配置默认关闭。显式开启后，仅允许状态、事件、系统设置、文件 prepare/chunk/complete 和番剧缓存 / 封面接口；拒绝管理接口、远程触发同步、SSE、任意目标、编码路径、升级和异常查询。事件查询只允许 after/limit，封面只允许合法文件名。
- 每请求最大 16 MiB，每入口最多 8 个并发；固定上游目标、跨机器全程证书校验。源站监听为回环；私有运行配置与证书私钥为 0600。
- 网关认证、业务认证、超限、错误接口与查询、伪造来源、来源限制及副本权限验证均通过。只有国内和香港两台通道节点运行 chitanda-transit；香港约 16 MiB 进程内存，未新增面板、数据库、容器或独立 HTTPS 进程。

## 实施与检查脚本

- `scripts/correct-data-gateway-topology.py`：备份并修正角色、源站元数据、两条测试通道、DNS 和固定出口。
- `scripts/stage-chitanda-migration.py`：在已复制公开产物基础上创建隔离副本，加入一致性快照、独立同步凭据、临时测试登录和限定接口。
- `scripts/verify-chitanda-migration.py`：正常后台写入、双向三片文件、修改、删除和完整性验证；应在创建测试登录后、收尾恢复账号前运行。
- `scripts/audit-chitanda-migration.py`：现行架构的入口、鉴权、固定目标、数据库与服务隔离检查；不读取明文密码到日志。
- `scripts/finish-chitanda-migration-test.py`：清理可识别的测试项目和文件、恢复副本账号、撤销一次性复制密钥，保留服务和同步配置。
- `scripts/verify-corrected-data-path.py`：摘要与直连基线；不会写入业务内容。
- 运行记录与凭据只放在控制机 `/var/lib/chitanda-data-test-deployment/`，私有配置分别为 `/etc/chitanda-migration.env` 与 `/etc/chitanda-data-test/config.json`。香港配置在 `/etc/chitanda-transit/config.json`。

## 正式切换前剩余工作

测试服务当前是隔离快照，不会追踪生产后续新增内容。正式切换需重新核对最新生产内容、补齐增量数据、调整正式业务凭据与指定同步对象、部署正式网站 HTTPS 入口后再切换流量，并验证回滚。现有自动 ACME 续期不等于所有测试副本自动换证；正式长期运行前需补齐证书分发和项目接入配置的管理流程。暂未启用自动跨优化机故障切换。
