# 2.23.0 统一登录与安全复查

日期：2026-10-21。面板 2.23.0、SSO 1.1.0，两个服务使用独立 Node.js 22.23.3。节点继续使用已审查的 2.12.0，本次没有改变节点协议或业务隧道配置。

## 修复与上线

- 中台接入 SSO 授权码与 PKCE S256，校验签名、issuer、audience、nonce、state、来源与有效期；只允许明确登记的 SSO `sub` 和管理角色。
- 精确匹配回调地址，拒绝附加查询参数、路径前缀与协议替换；修复授权码、刷新令牌与实际认证客户端未严格绑定的问题。
- 移除代码中的默认密码哈希、DNS 密钥和可推导的默认客户端密钥。确认三个系统客户端此前没有授权码/刷新令牌使用记录后，轮换为随机密钥；原用户密码、用户资料与签名私钥保留。
- SSO 改为仅 `sso.chitanda.net` 可用的 `__Host-` Cookie，拒绝生产根域 Cookie 配置，并撤销旧共享 Cookie 会话。升级后需要重新登录一次，避免其他子站收到统一账号凭据。
- 禁止把应用的 ID/access token 当作 SSO 管理端会话；JWT 算法及有效期强制校验，角色缺失时拒绝授权。
- 授权码、会话及刷新令牌按哈希存储。令牌绑定 SSO 会话，刷新令牌轮换；重放已消费的刷新令牌会撤销对应会话。
- 强制浏览器写入来源校验；中台保留 CSRF、来源绑定和在途请求撤销检查。注销、修改密码或撤销会话会使相应令牌失效。
- SSO 增加有界请求与密码校验并发限制、持久化的 IP/用户名登录失败记录、请求大小与超时限制；关闭两步验证的密码尝试单独限流。
- 修复启用两步验证后仍可重新生成密钥、通过 GET 修改密钥以及退出 Cookie 未设置 Max-Age=0 等问题。二维码在本站生成，不再把 TOTP 密钥发送给第三方二维码服务。
- 拒绝应用入口的 javascript/data URL 和包含账号密码的 URL；修复宽松角色解析及不真实的 email_verified 声明。
- SSO 使用低权限服务账号、私有数据库目录、只读系统目录、权限边界及内存/任务限制。
- 取消固定访客白名单，改为禁止 `110.42.32.0/24`、`168.138.209.0/24`，排除两台服务器自身地址及回环。
- 两端宝塔 WAF 开启 IDC 限制，保留可信客户端来源链；恢复 ARM WAF 缺失的 GeoIP 原生库，修复国外地址缓存及 IPv6 标签丢失，并使 IDC 判断先于通用白名单。
- 保留节点独立身份校验和必要的认证后端路径；管理 JSON 避免通用请求体解析器导致的 408，继续经过应用的权限、Origin、CSRF、参数与限流检查。
- 国内认证后端使用来源受限的独立香港 TCP 路径，端到端验证 SSO TLS；不依赖所管理业务隧道的状态。

授权码、精确回调及 PKCE 的实现依据 [OAuth 安全最佳实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)；身份令牌校验依据 [OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html#IDTokenValidation)。

## 验证范围

- 89 项面板后端测试通过，覆盖权限、来源、CSRF、限流、在途撤销、节点身份、隧道、证书、令牌和 OIDC 边界。
- 独立 SSO/面板联合测试通过，包含真实授权码流程、错误客户端、PKCE、重放、ID token 混用、来源校验、统一会话撤销以及浏览器个人设置。
- 4 项 SSO 安全单元测试与 420 项现有界面检查通过。
- `npm audit --omit=dev` 未报告已知生产依赖漏洞。Go 节点源码未改动，原审查结果见 [2.22.0](audit-2.22.0.md)。
- 公网验证自动登录、个人设置、后台 JSON 写入、管理 API 只读权限、越权拒绝、密钥撤销和文档访问；HSTS、CSP、nosniff 可见，无浏览器脚本异常。
- 实测机房来源连续访问 SSO 登录页被拒绝，认证后端公钥路径按受限例外可用；节点同步不经过机房浏览器限制。
- 正式验证时曾确认四个节点均在线并达到配置版本 119，启用的国内/香港业务通道就绪；备用国际节点 154.12.176.212 的跨境上报仍有间歇波动，未更改其原有业务配置。业务配置、证书、节点身份及业务令牌保留；测试凭据仅短期创建并在核验后撤销。

## 运行边界

认证中心或独立认证路径不可用时，中台拒绝管理操作；没有上线本地破窗登录。只读有效性缓存最多五秒，写入强制核验；API 密钥与节点身份不依赖浏览器 SSO。

IDC 判断受 WAF IP 数据库覆盖与更新影响，不等于能识别所有机房地址。机房来源调用管理 API 也会受限制。大流量攻击仍需 CDN、网络与源站层配合；本次未对生产进行压测或密码爆破，不声称不存在任何未知漏洞。
