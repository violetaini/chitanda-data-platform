# 2.22.0 安全复查（2026-10-21）

本次范围是数据中台面板、管理 API v1、节点安装/认证/配置分发、H2/H3/Stream 节点、HTTPS 业务入口、URL 请求目标校验、证书与 DNS 凭据边界，以及生产入口和运行时。未对其他业务站点的业务代码作同等范围审计。

## 修复与加固

- **会话撤销后的延迟写入**：旧逻辑只在接收请求头时检查会话。现在请求体读取完成、写入前再次检查会话是否仍存在、有效且属于原来源；退出登录后尚未读完的请求不能再修改配置。已有 API 密钥的撤销复核继续保留。
- **节点删除后的在途请求**：同步及卸载上报在读完请求体后复核当前节点身份，并使用最新节点对象，删除节点后不能继续以上一个对象修改状态。
- **请求资源控制**：新增有界的计数存储及全局/来源/身份并发占用限制。管理员写入每会话 60 次/分钟、并发 4；管理来源全部 API 请求 600 次/分钟；节点身份 120 次/分钟、并发 4；节点来源总请求 1200 次/分钟、并发 32。认证失败独立限制每来源 30 次/分钟，合法身份不会因失败计数被误当成无效身份。超限返回 429 和 Retry-After。
- **登录输入**：请求体上限 32 KB，严格接收 JSON 媒体类型；非字符串账密计为验证失败，避免对象强制转换引发内部错误。保留加盐 scrypt、同时最多两项密码校验、渐进延时、来源及账号累计锁定、重启后继续生效的锁定记录。
- **图片处理与日志**：头像处理增加全局单任务入口，限制排队图片造成的内存占用；保留 2 MB 输入及 1600 万像素限制。预期的 4xx/429 不再逐条输出应用错误日志；登录失败事件仍持久保存。
- **Nginx**：使用现有已验证的来源身份作为计数键，管理入口 10 请求/秒、节点路径 20 请求/秒，分别允许短时突发；登录独立 1 请求/秒，允许短时突发 5。每来源并发连接/请求限制 32，增加接收请求头、请求体及发送超时。保留管理来源限制、边缘身份校验、证书和回源目标。配置应用工具在 nginx -t 失败时还原原文件。移除重复的子级缓存头，恢复面板路径对 HSTS 等服务级安全头的继承；no-store 仍由服务级配置和应用响应提供。
- **节点依赖和头部限制**：节点 2.12.0 使用固定 Go 1.27.3、golang.org/x/net v0.60.0、x/crypto v0.57.0、x/text v0.42.0 重新构建；H2 和 H3 请求头限制为 16 KB。上游版本和观察补丁继续固定，不更改现有协议常量。
- **面板运行时**：采用独立 Node.js 22.23.3 程序及仅作用于本服务的 systemd 配置，下载来源和校验值记录在 panel-runtime.json。保持系统其他服务使用的 Node 程序不变。

## 复核通过的既有边界

管理面板和 API 均受现有来源 IP 限制；管理 API 使用独立高随机度密钥，摘要保存、分项授权、过期和撤销；写入需要 JSON。浏览器写入还校验会话、来源和 CSRF。管理 API 的读取/写入配额仍分别为每密钥 120/30 次每分钟，另有每来源配额。

节点安装使用短期且绑定节点及领取来源的凭据，下载文件校验大小和 SHA-256；发布文件路径限定为固定架构名单。每节点只获得其参与路径所需配置，管理 API 不返回节点令牌或证书私钥。

URL 接入只允许隧道配置中的 HTTPS 业务目标及路径范围；拒绝 IP 字面量、URL 内账密、异常编码及不允许的方法；实际拨号前检查解析地址，阻止回环、内网、共享和云元数据地址；拒绝业务重定向，不跳过 TLS 验证。业务正文限制和流式转发、现有单隧道令牌方案继续兼容。

生产配置文件权限为 0600，服务采用独立非 root 用户、NoNewPrivileges、ProtectSystem=strict、ProtectHome、PrivateTmp 及内存/任务限制。生产 Nginx 为 1.31.7，已核对官方当前安全公告范围。

## 验证及告警解释

- 85 项 Node 后端检查、420 项界面检查通过；补充复核账号及图片操作。
- 两项 Nginx 配置工具检查通过，涵盖幂等、来源/TLS/目标保留和校验失败还原。
- Gateway Go 测试通过；节点引擎测试在 Linux 私有挂载空间及 nobody 用户下通过，不使用生产节点状态目录。
- npm 生产依赖审计：0 项已知漏洞。
- 升级后 govulncheck 源码检查：实际导入包及可达调用链未检出已知漏洞。模块级仍报告 x/crypto 中不维护的 openpgp 包（GO-2026-5932）；节点不导入或调用此包。精简二进制的保守扫描仍可能报告该模块级告警，不能将它写成所有层次均为零告警。
- 多架构安装包均记录大小及 SHA-256；上线前后再次核对哈希和状态。

参考：[Go HTTP/2 安全公告](https://pkg.go.dev/vuln/GO-2026-6617)、[Go 漏洞数据库](https://vuln.go.dev/)、[Node.js 官方发布索引](https://nodejs.org/dist/index.json)、[Nginx 官方安全公告](https://nginx.org/en/security_advisories.html)。

这次检查不等同于独立外部渗透测试。限流、并发限制和 IP 控制用于降低爆破及应用层滥用风险；大流量攻击仍取决于 CDN 与运营商的防护能力。


## 线上复核结果

2.22.0 已部署，进程确实使用独立 Node.js 22.23.3。四个节点均报告 2.12.0、在线且配置版本为 119；当前两个启用方向均已就绪、无配置待同步。配置文件与上线前备份相比，账号、节点身份、根域名证书/私钥、隧道、路由和令牌一致。证书来源检查最终为 ready，现用证书有效。

国内和国际源站分别通过既有 data-test 业务入口调用同步状态和缓存查询，均返回 200 且通过 TLS 验证。管理 API 状态、节点、隧道和 OpenAPI 查询均返回 200；缺少密钥、权限不足、越权进入管理员接口及非授权来源被拒绝。临时核验密钥已撤销。

从国际源站直接请求国内公网管理入口，伪造 X-Real-IP、X-Forwarded-For 和 CF-Connecting-IP 为授权地址，仍返回 403。没有为了核验而解除白名单，也未在线上进行密码爆破或洪泛压测。最终 HTTPS 响应头复核确认 HSTS、CSP、nosniff、防嵌入和 no-store 均生效。
