# 2.25.0 自动备线验收

2026-10-30：控制端 2.25.0、节点 2.14.0。生产主站和 SSO 两组双向通道接入优化节点，业务域名、入口端口与原有令牌保持不变。生产私有配置、凭据和账号数据未纳入仓库。

| 场景 | 结果 |
| --- | --- |
| 正常主线 | 主站状态、事件只读接口及两向 SSO 签名请求成功 |
| 原主线双向丢包 | 四个逻辑方向自动使用优化备线，HTTPS 请求成功；首次主站请求约 1.84–2.04 秒 |
| 主线恢复 | 四个方向在后台探测恢复后自动回切；HTTPS 请求继续成功 |
| 优化节点停止 | 现有主线继续承接主站与 SSO 请求 |
| 全部恢复 | 主备探测通过，当前线路回到主线 |

SSO 测试只使用诊断会话校验和签名目录读取，响应签名及请求关联均验证通过；未签名请求保持返回 401。没有降级为不验证证书、共享业务凭据或扩大业务目标范围。

新增界面与 API 验证涵盖多备线创建、顺序调整、草稿刷新保留、双向反转、普通端点直连备线、备用节点授权范围、当前路径显示、重新编辑与删除，1440/390 像素布局无横向溢出。原通道界面的 117 项回归通过。

控制端 96 项测试通过；Linux 节点在非 root 账号下的 37 项完整集成测试通过，包括真实 H2/H3、多段链、Stream、TLS 身份验证、写请求不重放、GET 截断重试和大响应完整性。实际故障试验使用定向丢包及独立优化节点服务启停，并设置自动恢复措施；结束后删除测试规则并撤销短期凭据。

切换实测来自该次有限样本，不是所有网络状态下的时延承诺。已发送的写请求、大文件的在途连接及共用端点整机故障，边界见[使用说明](failover.md)。
