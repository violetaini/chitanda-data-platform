# 下载服务与访问白名单

在中台左侧选择 **下载服务**，可维护已部署下载入口的 IP 白名单。Docker 镜像与 GitHub 文件下载共用一个入口和名单。该功能需要面板 2.24.0、节点 2.13.1 或更新版本。

1. 填写一个 IP 或 CIDR 网段，以及可选备注，点击“添加”。支持 IPv4 和 IPv6。
2. 等待状态从“下发中”变成“已生效”，表示节点确认了当前版本，且本机下载程序和 HTTPS 证书已就绪。默认心跳间隔约 15 秒。
3. 移除条目后，该来源的后续请求将被拒绝。空白名单、暂停服务均拒绝所有来源。离线节点显示离线，恢复后领取最新策略。

“填入当前 IP”只填写输入框，仍需点击添加才会授权。编辑未保存的内容不会被页面自动刷新覆盖。白名单修改记入中台操作记录。

## 接入示例

假设入口域名为 `downloads.example.com`，业务服务器的公网出口 IP 已在白名单内：

```sh
docker pull downloads.example.com/library/alpine:latest
curl -fL 'https://downloads.example.com/https://raw.githubusercontent.com/OWNER/REPO/main/README.md'
```

不需要更改 Docker 守护进程的全局镜像源。入口地址沿用原下载程序的 URL 规则，不把下载内容经过控制面板。

## 部署边界

- 本模块管理**已部署**的下载程序，不会自动安装后端或发布 DNS。服务域名应直连承接节点；当前实现按 TCP 来源 IP 授权，不信任请求方自填的转发头。
- 节点本地配置 `downloadBackendEnabled: true` 后才提供此能力；控制端不能通过选择任意节点打开一个未知后端。下载程序固定只监听 `127.0.0.1:5000`，节点复用现有 HTTPS 端口和系统管理的泛域名证书。
- 同一节点当前承接一个下载服务。页面只管理已部署服务，不提供手工登记表单。部署时配置节点与域名，域名必须被该节点的公共证书覆盖。
- 不开放通用远程命令、可自定义的转发目标或额外公网管理端口。仅浏览器管理员可编辑名单；现有只读或节点/隧道管理 API 密钥不因此获得白名单管理权限。
- 已认证的隧道协议仍由原处理器校验 PSK，不经下载服务。下载白名单不能替代中台登录或改变其他通道的权限。
- 收到节点身份失效响应后清空下载许可并持久化撤销，避免下次离线启动恢复旧名单。控制端暂时不可达时保留最后已接收的配置，页面不会把离线状态显示为已生效。

原生服务的 systemd 模板见 [download.service](../deploy/tunnel-control/download.service)。先创建 `chitanda-download` 系统用户，将经过校验的下载程序放在模板路径，再启用该单元。此模板只管理原有下载程序，不会从未知来源自动下载二进制。
