# 数据通道测试与系统设置（控制端 2.6.0 / 节点 2.5.0）

控制端在后台自动检查启用的数据通道，默认每次完成后间隔 60 秒再次执行；不依赖浏览器打开。可在“系统设置”保存自动测活开关、间隔（15–3600 秒）及结果有效期（默认 180 秒）。有效期须为 120–86400 秒，至少比检查间隔长 90 秒，为排队和单次任务期限留出余量；设置约在 5 秒内影响下一次调度，不中断已开始任务，不更新线路配置版本。

在“数据通道”点击“测试”可手动检查，不必等待自动周期。如果同一通道已有自动检查，则直接接管该任务，避免重复工作。任务等待源节点下一次心跳，通常不超过 15 秒；完成后显示平均、最小、最大往返耗时、成功次数和时间。新检查期间保留并标注上次完成结果，收到新结果后替换。

## 实际检查范围

源节点先检查当前本地入口已就绪，再沿当前配置的 H2 / H3、SNI 和优化节点发起受鉴权的探测。优化节点通过该线路的真实反向会话要求目标节点拨通配置中的 `127.0.0.1:targetPort`；目标就在优化节点时直接检查其本地端口。收到目标确认后才记为成功。

RTT 为源节点发起探测至收到目标 TCP 端口确认的往返时间，包括线路建流和目标拨号开销。它不是 ICMP 延迟、浏览器至面板延迟，也不代表目标 HTTP / 数据库业务健康。探测不向业务端口发送正文，不计入业务流数或业务字节计数；目标服务仍可能记录一次短暂的 TCP 会话。

每次最多 3 个样本，间隔 150 ms；单次期限 8 秒，首次失败即停止。部分成功保留已有样本并标出原因。没有有效样本时不显示延迟；离线、监听未就绪、目标端口不可达、超时分别展示。

## 权限与生命周期

- `POST /tunnel/api/routes/:id/test` 仅接受空 JSON 对象，沿用管理员会话、精确来源白名单、CSRF 与 Origin 检查；不能指定任意地址或端口。
- 所有相关节点必须在线、配置版本一致且上报 `routeProbe: 1`。任务只发给该线路源节点，结果必须匹配源节点身份、任务 ID、线路及版本。
- 同一通道两次提交至少相隔 10 秒；同一源节点最多一个任务，全局最多 4 个任务。90 秒未完成显示超时。
- 任务不修改配置版本，不写入节点持久配置；每条现存通道的最近完成结果原子保存到 `CT_DATA/route-checks.json`（0600）。刷新和控制端重启后恢复，进行中的任务不跨重启重放；删除通道时清理对应缓存。
- 配置更新会取消待执行任务，完成的旧版本结果标记失效。手动测试中禁止重复点击；自动检查中仍可手动接管。节点最多保存 32 条短期结果，定期心跳重传，5 分钟后清除。
- 呼吸点只有在节点就绪、当前配置测活成功且结果未过期时显示绿色；失败、部分成功、过期、离线或待测显示红色。历史统计可以继续查看，不能据此判断当前可用。
- `GET /tunnel/api/settings` / `PATCH /tunnel/api/settings` 沿用管理员权限、IP / Origin / CSRF 检查，严格校验字段及范围，不允许通过设置更改来源白名单或任意探测目标。
- `5092` 管理端口继续禁止作为目标；没有放宽 TLS 校验、来源控制或节点凭据范围。
