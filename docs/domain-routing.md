# 业务域名、CNAME 与地区调度

更新时间：2026-10-19

## 数据路径

业务项目使用业务域名访问 HTTPS。数据通道页面以隧道为业务对象，创建时选择单向或双向，域名直接绑定到该隧道。业务域名的 CNAME 指向中台生成的 `ct-<绑定 ID>.tunnel.<解析区域>`：

- 单向隧道包含一条线路，目标只有一条 `default_view` A 记录，全部地区使用源节点的入口 IP。
- 双向隧道包含互为反向的两条线路，在同一张卡片管理。第一个方向的源节点是国内入口，第二个方向的源节点是国际入口；目标通过 `default_view` 指向国内，通过 `Abroad` 指向国际，其他地区回退到默认线路。

控制面板负责 DNS 配置和校验，业务流量始终经过节点上的 HTTPS 入口和所绑定的数据通道。

TLS 的 Host / SNI 仍为业务域名，而非 CNAME 目标。发布时控制端直接连接各入口节点的真实地址（单向一个、双向两个），以业务域名完成公开证书和 TLS 1.3 验证，校验证书有效期超过一天。CNAME 目标作为 DNS 调度名称，不需要额外申请入口证书。数据通道内部的 SNI / 工作区证书与业务 HTTPS 证书分别管理。

## 接入方式

1. 在 `dns.chitanda.net` 建立专用 API 用户，只授予需要的域名区域权限。现有华为云 AK / SK 保留在 DNS Manager，管理员无需开启 API 权限。
2. 在中台系统设置的“DNS 管理连接”中保存 HTTPS 根地址、用户 ID、API 密钥、区域 ID 和区域域名。保存前检查区域及默认 / 境外线路。
3. 到“数据通道”创建隧道，选择单向或双向，设置两端节点、协议和服务端口；双向需填写两个方向的端口，并按国内、国际放置入口节点。
4. 在对应隧道卡片展开“绑定业务域名”，填写域名及 TTL。单向源节点或双向两个源节点须已配置与该域名一致的 HTTPS 入口及 SSL。此功能接管已有入口的 DNS 调度，不会凭空创建新的业务适配器、开放任意目标或绕过原有逐跳鉴权。
5. 点击“预览 / 校验”，核对业务 CNAME 和目标 A 记录（单向共两条、双向共三条）及真实 SSL 校验结果，再点击“发布解析”。域名、CNAME 和地区入口均显示在隧道卡片内。

专用 API 连接写入 `CT_DATA/dns-provider.json`，权限 0600。快照和浏览器只返回连接元数据，不返回 API 密钥；节点配置中不包含 DNS 凭据。更新连接时留空密钥会保留已保存的值。

既有证书申请、续期和节点部署任务继续由 DNS Manager 管理。中台不会读取所有证书私钥，也不会通过普通域名 API 用户访问证书订单。新增业务入口应先完成节点侧的 HTTPS / 适配器配置和公开证书部署，再进行域名绑定。

## DNS 写入与回退

- 新绑定只允许接管与所选节点地址、地区完全一致的旧 A 记录。其他 TXT、AAAA、CNAME 或其他业务记录会导致预览停止，不会被覆盖。
- 预览有五分钟有效期，发布前重新验证 SSL、节点与 DNS 指纹；状态变化后必须重新预览。
- 初次接入先创建目标 A 记录（单向一个、双向两个），再把业务域名的旧 A 记录替换为 CNAME。已有目标地址变化使用原记录 ID 原地更新。
- 每次发布前在 `CT_DATA/dns-backup-<ID>-<时间>.json` 保存原记录。失败时重新读取实际 DNS 状态并与快照对齐，涵盖“服务端已执行但响应丢失”的情况；回退未能完成时明确标记错误。
- 已发布绑定不提供直接删除按钮，以免移除生产解析。移除业务时应先恢复或迁移其接入记录，核对两地实际请求，再进行运维清理。
- 当前按管理员选择的线路执行预览和发布，不自动进行跨节点容灾切换。节点地址改变后重新预览并发布。

## 发布与验证

控制端 2.9.0 与现有 2.7.0 节点兼容。升级时将已有域名关联的两条反向线路合并为双向隧道，只增添控制端分组和绑定关系，保留底层线路 ID、节点、端口、CNAME、线路版本及业务身份。其他旧线路显示为单向隧道，可通过卡片选择反向隧道主动合并。已绑定域名的隧道不能直接切换类型或删除。

只增量发布控制端模块、面板静态文件及版本文件，保留账号、CA、节点令牌和工作区状态。

`npm test` 包含 DNS 接管范围、预览指纹、原地更新、失败回退及密钥不回显测试；`npm run test:ui` 检查既有页面和证书设置回归。每次修改后同步日志并推送 GitHub，生产 DNS 快照和凭据留在服务器私有目录。
