# 业务域名、CNAME 与地区调度

更新时间：2026-10-19

## 数据路径

业务项目使用业务域名访问 HTTPS。数据通道页面以隧道为业务对象，创建时选择单向或双向，域名直接绑定到该隧道。业务域名的 CNAME 指向中台生成的 `ct-<绑定 ID>.tunnel.<解析区域>`：

- 单向隧道包含一条线路，目标只有一条 `default_view` A 记录，全部地区使用源节点的入口 IP。
- 双向隧道包含互为反向的两条线路，在同一张卡片管理。第一个方向的源节点是国内入口，第二个方向的源节点是国际入口；目标通过 `default_view` 指向国内，通过 `Abroad` 指向国际，其他地区回退到默认线路。

控制面板负责 DNS 配置和校验，业务流量始终经过节点上的 HTTPS 入口和所绑定的数据通道。

TLS 的 Host / SNI 仍为业务域名，而非 CNAME 目标。发布时控制端直接连接各入口节点的真实地址（单向一个、双向两个），以业务域名完成公开证书和 TLS 1.3 验证，校验证书有效期超过一天。CNAME 目标作为 DNS 调度名称，不需要额外申请入口证书。数据通道内部的 SNI / 工作区证书与业务 HTTPS 证书分别管理。

## 接入方式

1. 在 `dns.chitanda.net` 建立专用 API 用户，只授予需要的域名区域权限。现有华为云 AK / SK 保留在 DNS Manager，管理员无需开启 API 权限。
2. 在中台系统设置的“DNS 管理连接”中保存 HTTPS 根地址、用户 ID、API 密钥、区域 ID 和区域域名。保存前检查区域及默认 / 境外线路。
3. 到“数据通道”创建隧道，选择单向或双向，设置两端节点、协议和服务端口；双向需填写两个方向的端口，并按国内、国际放置入口节点。
4. 在创建窗口填写业务域名及 TTL（默认 1 秒，允许 1–3600 秒，发布时仍校验服务商最低要求），SNI 默认使用该业务域名，仍可自行修改。勾选“创建后由面板校验并发布解析”，保存时一并绑定域名、校验 SSL，再由面板生成并发布 CNAME 和地区 A 记录。节点切换不会覆盖手动输入的 SNI；留空业务域名可只创建数据通道。
5. 单向源节点或双向两个源节点须已配置与业务域名一致的 HTTPS 入口及 SSL。此功能接管已有入口的 DNS 调度，不会凭空创建新的业务适配器、申请公开 SSL 或绕过原有逐跳鉴权。域名须位于已接入的 DNS 区域内；自定义 SNI 仅影响内部协议握手，不会自动把它作为第二个业务域名发布解析。
6. 未勾选立即发布时，域名以草稿保存在隧道卡片内；也可在既有隧道展开“绑定业务域名”补充绑定。点击“预览 / 校验”，核对业务 CNAME 和目标 A 记录（单向共两条、双向共三条），再点击“发布解析”。发布失败会显示原因，可在卡片重试；不会把失败冒充为已发布。

专用 API 连接写入 `CT_DATA/dns-provider.json`，权限 0600。快照和浏览器只返回连接元数据，不返回 API 密钥；节点配置中不包含 DNS 凭据。更新连接时留空密钥会保留已保存的值。

既有证书申请、续期和节点部署任务继续由 DNS Manager 管理。中台不会读取所有证书私钥，也不会通过普通域名 API 用户访问证书订单。新增业务入口应先完成节点侧的 HTTPS / 适配器配置和公开证书部署，再进行域名绑定。

## DNS 写入与回退

- 新绑定只允许接管与所选节点地址、地区完全一致的旧 A 记录。其他 TXT、AAAA、CNAME 或其他业务记录会导致预览停止，不会被覆盖。
- 预览有五分钟有效期，发布前重新验证 SSL、节点与 DNS 指纹；状态变化后必须重新预览。
- 初次接入先创建目标 A 记录（单向一个、双向两个），再把业务域名的旧 A 记录替换为 CNAME。已有目标地址变化使用原记录 ID 原地更新。
- 每次发布前在 `CT_DATA/dns-backup-<ID>-<时间>.json` 保存原记录。失败时重新读取实际 DNS 状态并与快照对齐，涵盖“服务端已执行但响应丢失”的情况；回退未能完成时明确标记错误。
- 已发布绑定不提供直接删除按钮，以免移除生产解析。移除业务时应先恢复或迁移其接入记录，核对两地实际请求，再进行运维清理。
- 按管理员选择的线路接入；已发布绑定会自动维护当前节点的公网 IPv4 地址，不进行跨节点容灾切换。新增域名仍先预览并发布。

## 发布与验证

控制端 2.9.1 保留现有节点协议；业务域名与隧道 SNI 共用优化节点 443 时，优化节点需为 2.7.1，确保精确协议路径交由隧道处理，其余业务请求继续执行原来源、Host 与业务令牌校验。Stream 仍不使用 SNI。升级不自动覆盖已有自定义 SNI。

2.9.0 起将已有域名关联的两条反向线路合并为双向隧道，只增添控制端分组和绑定关系，保留底层线路 ID、节点、端口、CNAME、线路版本及业务身份。其他旧线路显示为单向隧道，可通过卡片选择反向隧道主动合并。已绑定域名的隧道不能直接切换类型或删除。

只增量发布控制端模块、面板静态文件及版本文件，保留账号、CA、节点令牌和工作区状态。

`npm test` 包含 DNS 接管范围、预览指纹、原地更新、失败回退及密钥不回显测试；`npm run test:ui` 检查既有页面和证书设置回归。每次修改后同步日志并推送 GitHub，生产 DNS 快照和凭据留在服务器私有目录。


## TTL 调整

创建隧道、独立绑定表单和后端缺省值均为 1 秒。已有绑定可通过管理员 PATCH `/tunnel/api/domains/<id>` 提交 `{ "ttl": 1 }` 保存期望值，再沿用预览和发布流程更新业务 CNAME 及所有地区 A 记录。保存配置不直接写 DNS，已发布绑定的未发布 TTL 修改会明确标记；旧预览自动作废。

更新按原记录原位执行并回读服务商实际 TTL，保留业务域名、CNAME、地区、地址及记录身份。发布失败沿用原记录快照恢复机制；服务商最低 TTL 高于请求值时停止发布。

## 节点 IP 自动更新（2.10.0）

节点管理只显示节点身份、状态与资源；业务域名按隧道管理，多条隧道各自显示所属域名、地区和自动更新结果，节点卡片不再列出单个 HTTPS 入口。

已发布绑定默认启用 IP 自动更新。控制端从通过独立凭据鉴权的节点心跳识别地址，不采用节点请求体中的任意 host 字段。后台每 5 秒调度，首次或节点地址变化时核对相关绑定，未变化的绑定每 5 分钟复核；无需打开页面。一次 IP 变化会逐条处理所有关联的已发布绑定。

更新前仍用业务域名对新地址做公开证书、TLS 1.3、有效期验证，并核对业务 CNAME、目标 A 记录、地区、启用状态和专属管理标记。只原位更新这些 A 记录的地址，保留记录 ID、CNAME、现有 TTL、权重与地区。尚未发布的 TTL 修改和域名草稿不会被自动发布；暂停的隧道保留绑定并继续维护地址。

自动发布与人工发布共用互斥锁，期间心跳继续采集运行数据，地址变更留待下一次心跳识别。DNS 备份和失败回退仍有效；自动回退仅恢复本次地址修改，不创建已被外部删除的记录或覆盖已被外部接管的记录。外部删除、额外记录、CNAME 改动、管理标记或启用状态变化时停止自动写入并显示原因。

成功与失败状态、最近核验和更新时间保存在绑定的 addressSync 元数据中。失败保留原解析，以 30 秒到 5 分钟退避重试；等待重试的状态在控制端重启后保留。隧道详情显示“IP 变动自动更新”及待处理原因。当前机制维护现有 IPv4 A 记录，不自动配置新节点入口、证书或源站白名单。
