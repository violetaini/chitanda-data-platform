# SSL 证书的三种来源

在“系统设置 → SSL 证书”添加或编辑配置。可保存多份配置；每个节点使用一份当前证书，证书可覆盖多个域名或泛域名。证书须覆盖全部选中节点的实际 HTTPS 入口域名，节点入口仍由安装配置登记。SNI 在隧道中设置，内部节点身份证书保持独立。

## 自动申请与续签

中台通过 Let’s Encrypt ACME DNS-01 申请公网证书。先连接 DNS Manager 签名 API，填写所属区域内的域名，选中应用节点并同意 CA 条款。通知邮箱可选。中台保存独立 ACME 账户，私钥仅存于私有数据目录，使用已有 Node.js / OpenSSL 环境，无需节点安装申请程序。

每小时检查有效期，默认提前 30 天续签，可设置 7–60 天。验证记录使用 TXT，签发后仅移除本次生成的值，保留其他记录值。DNS 面板返回带引号 TXT 时也可清理；失败保存私有重试日志并在后续任务补清理。网络请求及 nonce 错误有有限重试；失败保留现有证书。

自动模式不覆盖已有验证 CNAME。存在其他验证委托时，应按实际 DNS 布局配置，或使用已有 DNS 面板续签模式。

## DNS 面板续签并同步

填写 DNS 面板中的证书订单 ID。DNS 面板负责申请、续签和自己的自动任务；中台每 60 秒读取此订单的证书。只有证书或私钥变化才增加节点配置版本。读取失败、证书不匹配、未生效、临近到期或同一配置下回退到更早到期的版本时保留已保存证书并重试。

连接使用系统设置已有的 DNS API 地址和身份。上游管理员 API 支持 `/api/cert/order`；受限账号建议部署仓库的 [指定订单导出组件](../integrations/dns-manager-certificate-export.php)：

1. 将组件安装为 DNS Manager 的 `app/controller/DatahubCertificate.php`。
2. 在 `route/app.php` 的现有 `AuthApi` 路由组内添加 `Route::post('/cert/datahub/order', 'datahubCertificate/order');`。
3. 在程序根目录 `config/datahub-certificate-scopes.json` 配置受限 API 用户可读的订单 ID，例如 `{"users":{"123":[1,2]}}`。文件由管理员维护，置于网站 public 目录外，建议 root 所有、PHP 运行组可读、0640。保留现有 PHP open_basedir 限制。

组件保留原签名认证，仅导出明确授权且已签发的订单，不给受限用户管理员权限。中台优先调用此接口，再兼容原管理员接口；不会在公开响应、日志或审计写出证书私钥。DNS 系统升级后需保留组件与路由；新增订单需管理员显式授权。

## 自行上传与维护

可选择证书链文件和私钥文件，也可粘贴 PEM。保存时验证完整链、有效期、域名和密钥匹配，校验失败不替换原配置。到期前自行续签，再上传新文件。编辑时两项均留空可保留现有证书，私钥不回显。

## 下发与加载

三种来源统一通过节点原有认证配置下发，节点正常同步约 15 秒。内置 HTTPS 入口在内存中热更新；外置 Nginx 入口原子写入单个 0600 PEM bundle，由已有固定本机服务执行配置检查与重载，通常再等最多约 15 秒。

面板根据节点真实加载的证书指纹显示已应用、待应用或离线。应用状态与证书任务状态分开：外部系统暂不可用时，节点可继续使用上次证书。移除配置恢复节点原有备用证书源；其有效性仍由本机维护。无需重置节点身份、隧道令牌或重建业务通道。

公网证书与节点内部身份不同：原生 Stream 不使用 TLS 证书；H2/H3 节点身份默认沿用工作空间证书。业务源站网站的证书和管理面板网站证书仍由各自部署管理。
