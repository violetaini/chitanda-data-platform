# 多条路径与多段路径

两机与多机使用同一套配置。控制端独立于业务路径，不计入机器数量。

| 方式 | 示例 | 优化机的职责 |
| --- | --- | --- |
| 两机 | 国内端 ↔ 优化机 | 同时是隧道终点 |
| 三机 | 国内端 ↔ 优化机 ↔ 国际端 | 中间转交 |
| 多段 | 国内端 ↔ 优化机 A ↔ 优化机 B ↔ 国际端 | 逐段转交 |
| 多条 | 国内端分别经优化机到多个国际端 | 共用优化机、各自独立的隧道 |

## 添加

1. 登记并安装实际参与的节点。中间机器选择“优化机”；两端可以选择入口节点或兼任入口的优化机。
2. 打开数据通道，填写名称，选择起点和终点。
3. 选择经由的优化机。两机且一端本身是优化机时，选择直达；多段时点“添加一段”，按实际经过的先后顺序选择。预览显示完整路径和机器数量。
4. 填写本机接入端口与终点服务端口。双向时补充反向端口，面板自动反转完整优化机顺序。
5. 协议默认 H2，可选 H3 或原生 Stream。“域名与高级设置”按需展开。
6. 保存后等待各节点同步，再点测试。测试验证完整路径与最终 TCP 服务端口；业务 HTTP 的鉴权和内容仍需实际调用核验。

端口只监听回环。原始 TCP 业务访问起点 `127.0.0.1:接入端口`，在终点交给 `127.0.0.1:服务端口`。业务 URL、公开证书、固定上游的部署步骤见 [URL 接入](url-access.md)。仅添加路径不会自动在新入口发布公网业务服务。

每条路径最多包含 8 台不同优化机，禁止重复与回环。路径中的协议和 SNI 统一应用于每段；各段使用各自节点身份、派生凭据及优化机密钥。H3 需要每一段允许 UDP，Stream 需要允许对应 TCP 端口。中间机器仅收到自己参与的路径及相邻对端所需配置，不获得控制端 CA 私钥或其他节点的管理凭据。

同一优化机可以服务多条路径，同一终点也可以接收多条隧道。同一源节点的接入端口必须互不冲突。当前为显式指定路径，不会自动负载均衡或故障切换。断开中间节点时整条路径报错，不会绕过中间节点直达终点。

## 兼容与维护

控制面板 2.14.2、节点 2.8.1 起支持串联多优化机。参与多段路径的节点应全部升级到该版本；旧单优化机配置和身份保留兼容。节点仍为单个 Go 进程，自动更新沿用系统设置。

配置保存有序的 `relayIds`，兼容字段 `relayId` 为首段。双向隧道保存相反顺序的两条底层线路。拓扑、节点权限、证书覆盖、心跳状态与测活均按完整路径计算；修改或删除中间节点受到关联隧道和业务域名约束。

控制端从鉴权心跳自动记录多段协议能力。只有整条路径全部参与节点确认支持时，才下发多段线路及对应凭据；旧版节点不会收到可能被当作较短路径执行的配置。该能力记录持久保存，控制端重启不必重复清空正常路径。
